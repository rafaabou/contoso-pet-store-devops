## 1. What Is Grype

Grype is a vulnerability scanner for container images and filesystems, developed by Anchore. It is designed to be fast, accurate, and easy to integrate into CI/CD pipelines. Grype works by scanning a container image's package manifest and comparing the identified packages against known vulnerabilities from multiple advisory databases.

### 1.1 Overview

Grype is a project by Anchore that provides:

- **Vulnerability Scanning**: Detects CVEs in container images and filesystems
- **Multi-Database Support**: Uses NVD, GitHub Advisory Database, and OS-specific advisories
- **Fast Scanning**: Optimized for speed with parallel processing
- **SARIF Output**: Native support for GitHub Security tab integration
- **JSON/Table Output**: Multiple output formats for different use cases
- **Ignore Files**: Support for `.grypeignore` to suppress known false positives

### 1.2 Architecture

Grype's architecture consists of:

- **Syft Integration**: Uses Syft to generate SBOM from container images
- **Vulnerability Database**: Downloads and caches vulnerability data from multiple sources
- **Matcher Engine**: Matches detected packages against vulnerability databases
- **Reporter**: Outputs results in multiple formats

### 1.3 Supported Targets

| Target Type | Supported Formats |
|---|---|
| Container Images | Docker, OCI, Podman, TAR |
| Filesystem | Source code directories, SBOM files |
| SBOM | CycloneDX, SPDX (generated by Syft) |

### 1.4 Comparison with Other Scanners

| Feature | Grype | Trivy | Snyk Container | Twistlock |
|---|---|---|---|---|
| Open Source | Yes (Apache 2) | Yes (Apache 2) | Freemium | Commercial |

## 2. Why Use Grype

### 2.1 Speed

Grype is one of the fastest vulnerability scanners available. It can scan a typical container image in under 5 seconds, making it ideal for CI/CD pipelines where speed matters.

### 2.2 Accuracy

Grype uses multiple vulnerability databases and a sophisticated matching algorithm to minimize false positives while maintaining high detection rates.

### 2.3 Simplicity

Grype requires zero configuration to start scanning. It works out of the box with sensible defaults:

```bash
# Scan an image with zero configuration
grype nginx:latest

# Scan an SBOM file
grype sbom:sbom.json
```

### 2.4 Anchore Ecosystem

Grype is part of the Anchore ecosystem, which includes:

- **Syft**: SBOM generation
- **Grype**: Vulnerability scanning
- **Anchore Enterprise**: Commercial vulnerability management platform

### 2.5 Active Development

Grype is actively maintained with regular releases and vulnerability database updates. It has a strong community and is widely used in production environments.

## 3. Real-World Breaches

### 3.1 Log4Shell (CVE-2021-44228)

**What happened**: A critical RCE vulnerability in Apache Log4j affected millions of Java applications worldwide.

**Grype detection**:

```bash
grype my-java-app:latest | grep -i log4j
```

**Impact**: Equifax, Apple, Amazon, Twitter, and thousands of other organizations were affected.

### 3.2 Spring4Shell (CVE-2022-22965)

**What happened**: A critical RCE vulnerability in Spring Framework affecting Spring Boot applications.

**Grype detection**:

```bash
grype my-spring-app:latest | grep -i spring
```

### 3.3 OpenSSL Heartbleed (CVE-2014-0160)

**What happened**: A critical vulnerability in OpenSSL allowing attackers to read server memory.

**Grype detection**:

```bash
grype ubuntu:20.04 | grep -i openssl
```

### 3.4 Dependency Confusion (2021)

**What happened**: Attackers published malicious packages with names matching internal packages on public registries.

**Grype detection**: Grype can identify all dependencies in an image, helping detect unexpected public dependencies.

### 3.5 SolarWinds Supply Chain Attack (2020)

**What happened**: Attackers compromised SolarWinds Orion build system, injecting backdoors into software updates.

**Grype detection**: Grype's SBOM generation and dependency tracking can help audit the software supply chain.

### 3.6 Codecov Supply Chain Attack (2021)

**What happened**: Attackers modified the Codecov Bash Uploader to exfiltrate environment variables.

**Grype detection**: While Grype doesn't detect secrets directly, it can identify vulnerable dependencies that might be exploited in supply chain attacks.

## 4. Installation

### 4.1 Quick Install (Recommended)

```bash
# Install via the official install script
curl -sSfL https://raw.githubusercontent.com/anchore/grype/main/install.sh | sh -s -- -b /usr/local/bin

# Verify installation
grype version
```

### 4.2 Package Managers

```bash
# Ubuntu/Debian (via Anchore repository)
curl -1sLf 'https://raw.githubusercontent.com/anchore/grype/main/install.sh' | sudo -E bash
sudo apt-get install grype

# Homebrew (macOS)
brew install grype

# Snap
sudo snap install grype

# AUR (Arch Linux)
yay -S grype
```

### 4.3 Docker

```bash
# Run Grype as a container
docker run --rm \
  -v /var/run/docker.sock:/var/run/docker.sock \
  anchore/grype:latest nginx:latest

# Scan a local directory
docker run --rm \
  -v /path/to/project:/project \
  anchore/grype:latest dir:/project
```

### 4.4 Binary Download

```bash
# Download the latest release
GRYPE_VERSION=$(curl -s https://api.github.com/repos/anchore/grype/releases/latest | grep -o '"tag_name": "v[^"]*"' | cut -d'"' -f4)
curl -LO "https://github.com/anchore/grype/releases/download/${GRYPE_VERSION}/grype_${GRYPE_VERSION#v}_linux_amd64.tar.gz"
tar -xzf "grype_${GRYPE_VERSION#v}_linux_amd64.tar.gz"
sudo mv grype /usr/local/bin/
```

### 4.5 Kubernetes Deployment

```bash
# Deploy Grype as a Kubernetes Job
kubectl apply -f - <<EOF
apiVersion: batch/v1
kind: Job
metadata:
  name: grype-scan
spec:
  template:
    spec:
      containers:
      - name: grype
        image: anchore/grype:latest
        args:
        - nginx:latest
        - --output
        - json
      restartPolicy: Never
  backoffLimit: 1
EOF
```

## 5. Configuration

Grype can be configured via a YAML file (`.grype.yaml` or `grype.yaml`):

```yaml
# .grype.yaml
output: table

vulnerability:
  severity:
    - critical
    - high
  ignore-unfixed: true
  compare:
    by: exact

db:
  auto-update: true
  cache-dir: /tmp/grype-cache
  update-url: https://grype.anchore.io/databases

search:
  scope: all-layers
  nested: "false"

match:
  java:
    using-cpe: true
  python:
    using-cpe: true
  ruby:
    using-cpe: true
  javascript:
    using-cpe: true
  dotnet:
    using-cpe: true
```

### 5.2 Environment Variables

```bash
# Skip DB update
export GRYPE_DB_AUTO_UPDATE=false

# Set cache directory
export GRYPE_CACHE_DIR=/tmp/grype-cache

# Set output format
export GRYPE_OUTPUT=json

# Set severity filter
export GRYPE_VULNERABILITY_SEVERITY=high,critical
```

## 6. Core Concepts

### 6.1 SBOM-Based Scanning

Grype works by first generating an SBOM (Software Bill of Materials) from the target, then matching packages against vulnerability databases. This two-step approach allows:

- Reuse of SBOMs across multiple scans
- Integration with Syft for detailed SBOM generation
- Comparison of different vulnerability databases

### 6.2 Vulnerability Matching

Grype matches packages using multiple strategies:

- **Exact Version Match**: Matches exact package versions
- **Range Match**: Matches version ranges
- **CPE Match**: Matches Common Platform Enumeration identifiers
- **Language-Specific Match**: Uses ecosystem-specific vulnerability data

### 6.3 Database Sources

Grype uses multiple vulnerability databases:

- **NVD**: National Vulnerability Database (US government)
- **GitHub Advisory Database**: Covers npm, pip, Go, RubyGems, etc.
- **OS-Specific Advisories**: Alpine, Debian, Ubuntu, RHEL, SUSE, Amazon Linux, etc.

### 6.4 Scope

Grype supports different scan scopes:

- **Squashed**: Scan the squashed image (single layer)
- **All Layers**: Scan all image layers
- **All Packages**: Include packages from all layers

### 6.5 Output Formats

| Format | Description |
|---|---|
| table | Human-readable table (default) |
| json | Machine-readable JSON |
| sarif | SARIF format for GitHub Security |
| cyclonedx | CycloneDX SBOM format |
| template | Custom Go template |

## 7. Usage Guide

### 7.1 Scanning Container Images

```bash
# Scan a remote image
grype nginx:latest

# Scan a local image
grype docker-archive:my-app.tar

# Scan with specific severity
grype --only-fixed --fail-on high nginx:latest

# Scan and output JSON
grype --output json nginx:latest > results.json

# Scan and generate SARIF
grype --output sarif nginx:latest > results.sarif

# Scan with ignore file
grype --ignore .grypeignore nginx:latest

# Scan with specific database
grype --db some-db:latest nginx:latest

# Scan without updating DB
grype --no-update nginx:latest

# Scan with custom timeout
grype --timeout 30m nginx:latest
```

### 7.2 Scanning SBOM Files

```bash
# Scan a Syft-generated SBOM
grype sbom:sbom.json

# Scan a CycloneDX SBOM
grype sbom:sbom.cdx.json

# Scan an SPDX SBOM
grype sbom:sbom.spdx.json
```

### 7.3 Scanning Filesystems

```bash
# Scan a directory
grype dir:/path/to/project

# Scan with specific scope
grype dir:/path/to/project --scope all-layers

# Scan and output JSON
grype dir:/path/to/project --output json
```

### 7.4 Scanning Docker Archives

```bash
# Scan a Docker save archive
grype docker-archive:my-image.tar

# Scan an OCI archive
grype oci-archive:my-image.tar

# Scan a Podman archive
grype podman-archive:my-image.tar
```

### 7.5 Client/Server Mode

```bash
# Start the Grype server
grype server --listen 0.0.0.0:8080

# Scan using the remote server
grype --server http://grype-server:8080 nginx:latest
```

## 8. Custom Rules and Policies

### 8.1 Ignore File Syntax

The `.grypeignore` file supports multiple ignore patterns:

```
# CVE-2021-44228 - Log4Shell
CVE-2021-44228

# Specific advisory with comment
GHSA-xxxx-xxxx-xxxx  # Not applicable to our deployment

# Package-specific ignore
CVE-2022-1234  # Affected package is not used in production

# Wildcard ignore
CVE-2023-*  # Ignore all 2023 CVEs (not recommended)
```

### 8.2 Custom Database Configuration

```yaml
# .grype.yaml
db:
  auto-update: false
  cache-dir: /var/cache/grype
  update-url: https://custom-db.example.com/grype
  ca-cert: /path/to/ca.pem
  skip-validation: false
```

### 8.3 Custom Matching Rules

```yaml
# .grype.yaml
match:
  java:
    using-cpe: true
    version-cpe: true
  python:
    using-cpe: true
  ruby:
    using-cpe: true
  javascript:
    using-cpe: true
  dotnet:
    using-cpe: true
```

### 8.4 Severity-Based Policies

```yaml
# .grype.yaml
output: table

vulnerability:
  severity:
    - critical
    - high
  ignore-unfixed: true
  compare:
    by: exact

fail-on-severity:
  - critical
  - high
```

## 9. Integration

### 9.1 GitHub Actions

```yaml
# .github/workflows/grype-scan.yml
name: Grype Security Scan
on:
  push:
    branches: [main, develop]
  pull_request:
    branches: [main]

jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Run Grype vulnerability scanner
        uses: anchore/scan-action@v6
        id: grype
        with:
          image: my-app:${{ github.sha }}
          fail-build: true
          severity-cutoff: high
          output-format: sarif

      - name: Upload Grype scan results
        uses: github/codeql-action/upload-sarif@v3
        if: always()
        with:
          sarif_file: ${{ steps.grype.outputs.sarif }}

      - name: Run Grype FS scanner
        uses: anchore/scan-action@v6
        with:
          path: .
          fail-build: true
          severity-cutoff: high
          output-format: table
```

## 11. Troubleshooting

### 11.1 Issue: Database Download Timeout

**Symptom**: `unable to fetch vulnerability database`

**Fix**:
```bash
# Increase timeout
grype --timeout 30m nginx:latest

# Use a local cache
export GRYPE_CACHE_DIR=/var/cache/grype
grype nginx:latest

# Use a mirror
export GRYPE_DB_UPDATE_URL=mirror.example.com/grype-db
```

### 11.2 Issue: Permission Denied

**Symptom**: `permission denied` when scanning

**Fix**:
```bash
# Run with sudo
sudo grype nginx:latest

# Or add user to docker group
sudo usermod -aG docker $USER
```

### 11.3 Issue: Out of Memory

**Symptom**: `Killed` or `out of memory` error

**Fix**:
```bash
# Use Docker with memory limit
docker run --rm --memory=2g anchore/grype nginx:latest

# Scan specific layers only
grype --scope squashed nginx:latest
```

### 11.4 Issue: False Positives

**Symptom**: Vulnerability reported but not applicable

**Fix**:
```bash
# Create ignore file
echo "CVE-2021-44228" >> .grypeignore

# Use only-fixed to ignore unfixed
grype --only-fixed nginx:latest
```

### 11.5 Issue: Slow Scanning

**Symptom**: Scan takes too long

**Fix**:
```bash
# Update DB first
grype --no-update nginx:latest

# Use squashed scope
grype --scope squashed nginx:latest

# Use client/server mode
grype server --listen 0.0.0.0:8080 &
grype --server http://localhost:8080 nginx:latest
```

### 11.6 Issue: SARIF Output Format Issues

**Symptom**: SARIF file not recognized by GitHub

**Fix**:
```bash
# Ensure proper SARIF format
grype --output sarif nginx:latest > results.sarif

# Verify SARIF validity
cat results.sarif | jq '.version'
```

### 11.7 Issue: Kubernetes RBAC Errors

**Symptom**: `Error: forbidden` when scanning cluster

**Fix**:
```bash
# Create proper RBAC
kubectl apply -f grype-rbac.yaml

# Check permissions
kubectl auth can-i list pods --as=system:serviceaccount:grype-system:grype-scanner
```

### 11.8 Issue: Version Mismatch

**Symptom**: `DB schema version mismatch`

**Fix**:
```bash
# Force DB update
grype --update-db nginx:latest

# Or manually clear cache
rm -rf /tmp/grype-cache
grype nginx:latest
```

### 11.9 Issue: Large Image Scanning

**Symptom**: Scan fails on very large images

**Fix**:
```bash
# Increase timeout
export GRYPE_TIMEOUT=60m

# Use Docker with more resources
docker run --rm --cpus=4 --memory=4g anchore/grype large-image:latest
```

### 11.10 Issue: Alpine Linux Vulnerabilities Not Found

**Symptom**: No vulnerabilities detected for Alpine image

**Fix**:
```bash
# Force Alpine DB download
grype --update-db nginx:latest

# Verify Alpine DB
grype --list-db
```

### 11.11 Issue: CI/CD Pipeline Timeout

**Symptom**: Scan times out in CI/CD pipeline

**Fix**:
```yaml
# GitHub Actions - increase timeout
- name: Grype Scan
  uses: anchore/scan-action@v6
  timeout-minutes: 30
  with:
    image: my-app:latest
```

### 11.12 Issue: Multiple Image Tags

**Symptom**: Cannot scan image with multiple tags

**Fix**:
```bash
# Use full image reference
grype myregistry/myapp:tag1

# Or scan each tag separately
grype myregistry/myapp:tag1
grype myregistry/myapp:tag2
```

### 11.13 Issue: Grype Server Connection Refused

**Symptom**: `connection refused` when connecting to Grype server

**Fix**:
```bash
# Check server is running
curl http://grype-server:8080/healthz

# Check network connectivity
kubectl exec -it client-pod -- curl http://grype-server:8080/healthz
```

### 11.14 Issue: Unicode and Internationalized Characters

**Symptom**: Incorrect vulnerability matching for international packages

**Fix**:
```bash
# Use JSON output for precise matching
grype --output json nginx:latest | jq '.matches[] | select(.vulnerability.id | contains("特殊字符"))'
```

### 11.15 Issue: Garbage Collection of Old Reports

**Symptom**: Disk space issues from accumulated scan reports

**Fix**:
```bash
# Use Kubernetes CronJob with TTL
apiVersion: batch/v1
kind: CronJob
metadata:
  name: grype-cleanup
spec:
  schedule: "0 2 * * *"
  jobTemplate:
    spec:
      ttlSecondsAfterFinished: 86400
      template:
        spec:
          containers:
          - name: cleanup
            image: anchore/grype:latest
            command:
            - /bin/sh
            - -c
            - |
              kubectl delete vulnerabilityreports --all-namespaces \
                --field-selector=status.phase=Complete \
                --field-selector=metadata.creationTimestamp<$(date -d "7 days ago" -Iseconds)
```

## 12. Tips and Best Practices

### 12.1 Use Syft for SBOM Generation

Grype works best when combined with Syft for SBOM generation:

```bash
# Generate SBOM with Syft
syft nginx:latest -o json > sbom.json

# Scan SBOM with Grype
grype sbom:sbom.json
```

### 12.2 Cache the Vulnerability Database

```bash
# Pre-download DB for faster scans
grype --no-update nginx:latest

# Use persistent cache
export GRYPE_CACHE_DIR=/var/cache/grype
mkdir -p $GRYPE_CACHE_DIR
```

### 12.3 Use Client/Server Mode

For frequent scans, run a Grype server to avoid re-downloading the DB:

```bash
# Start server
grype server --listen 0.0.0.0:8080

# Scan using server
grype --server http://grype-server:8080 nginx:latest
```

### 12.4 Use Ignore Files for Accepted Risks

```bash
# Create .grypeignore
echo "CVE-2021-44228" >> .grypeignore
echo "# Reason: We use custom Log4j configuration that mitigates this" >> .grypeignore
```

### 12.5 Combine with Other Security Tools

Use Grype alongside:
- **Trivy**: For IaC scanning and secret detection
- **Syft**: For detailed SBOM generation
- **Cosign**: For image signing and verification
- **OPA/Gatekeeper**: For policy enforcement

### 12.6 Monitor for New Vulnerabilities

```bash
# Schedule daily scans
# crontab
0 6 * * * grype myregistry/myapp:latest --output json --output /var/log/grype/$(date +\%Y\%m\%d).json
```

### 12.7 Use Severity-Based Policies

```bash
# Only report CRITICAL
grype --severity critical nginx:latest

# Report HIGH and CRITICAL
grype --severity high,critical nginx:latest
```

### 12.8 Scan Base Images Separately

```bash
# Scan base image
grype --severity critical ubuntu:22.04

# Scan application layer only
grype --scope squashed my-app:latest
```

### 12.9 Use VEX for False Positive Management

```json
{
  "bomFormat": "CycloneDX",
  "specVersion": "1.4",
```

## 15. Real-World Examples

### 15.1 Contoso Pet Store - Container Security

**Scenario**: Contoso Pet Store runs a microservices architecture on Kubernetes with 15 container images in production.

#### 15.1.1 CI/CD Pipeline Integration

```yaml
# .github/workflows/petstore-grype.yml
name: Pet Store Grype Scan
on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build-and-scan:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        service:
          - api-gateway
          - product-service
          - cart-service
          - order-service
          - user-service
          - payment-service
          - notification-service

    steps:
      - uses: actions/checkout@v4

      - name: Build Docker image
        run: docker build -t petstore/${{ matrix.service }}:${{ github.sha }} ./services/${{ matrix.service }}

      - name: Run Grype vulnerability scanner
        uses: anchore/scan-action@v6
        with:
          image: petstore/${{ matrix.service }}:${{ github.sha }}
          format: sarif
          output-file: grype-${{ matrix.service }}.sarif
          fail-build: true
          severity-cutoff: high

      - name: Upload SARIF results
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: grype-${{ matrix.service }}.sarif

      - name: Generate SBOM
        uses: anchore/sbom-action@v0
        with:
          image: petstore/${{ matrix.service }}:${{ github.sha }}
          format: cyclonedx
          output-file: sbom-${{ matrix.service }}.cdx.json
```

#### 15.1.2 Kubernetes Security Policies

```yaml
# petstore-kyverno-policy.yaml
apiVersion: kyverno.io/v1
kind: ClusterPolicy
metadata:
  name: petstore-image-scan
spec:
  validationFailureAction: Enforce
  background: true
  rules:
  - name: require-grype-scan
    match:
      any:
      - resources:
          kinds:
          - Pod
          namespaces:
          - petstore-production
          - petstore-staging
    validate:
      message: "Image must pass Grype security scan (no CRITICAL vulnerabilities)"
      pattern:
        spec:
          containers:
          - name: "*"
            image: "!petstore/*:*@sha256:*"
            imagePullPolicy: Always
```

#### 15.1.3 Monitoring Dashboard

```yaml
# prometheus-rules.yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: grype-alerts
spec:
  groups:
  - name: grype
    rules:
    - alert: GrypeCriticalVulnerability
      expr: |
        increase(grype_vulnerabilities_total{severity="critical"}[1h]) > 0
      for: 5m

        severity: critical
      annotations:
        summary: "New CRITICAL vulnerability detected"
        description: "Grype detected {{ $value }} new CRITICAL vulnerabilities in the last hour"

    - alert: GrypeScanFailure
      expr: |
        increase(grype_scan_errors_total[1h]) > 0
      for: 5m
```
